# Melodee Android — Toolchain Upgrade Results

**Date:** 2026-11-26
**Branch:** `chore/upgrade-android-toolchain`
**Starting commit:** `e82217a7e38595e7a2edc996455d613873a60b86` (`main`)
**Scope:** build toolchain modernization only; no product, media, authentication, visual or Android Auto feature changes.

## Executive Summary

The Android build toolchain was upgraded from Gradle 8.13 / AGP 8.13.2 / Kotlin 2.2.21 to Gradle 9.6.1 / AGP 9.5.3 / Kotlin 2.4.21. The application module now uses AGP built-in Kotlin, the public `android` DSL and Gradle Kotlin DSL with no legacy AGP opt-outs. KSP was upgraded to 2.3.14 for AGP 9 compatibility. JDK 21 is the declared toolchain while Java/Kotlin bytecode remains at 17 for Android API compatibility.

A full clean build without the Gradle build cache completed successfully: debug and R8 release APKs, 31 core unit tests, Android Lint, and the instrumentation APK all passed. The real `MediaLibrarySmokeTest` passed 1/1 on a Pixel 9 Pro XL API 37 emulator, and manual phone validation covered launch, the four destinations, actual demo audio, sequential track transition, background playback, seeking, shuffle/repeat and queue/position restoration. Android Auto manifest and packaged-artifact declarations were preserved and verified. DHU and physical-vehicle testing were not available and remain outstanding qualification requirements, as does runtime validation of the unsigned release artifact.

**Overall status:** toolchain migration complete and suitable as the development baseline; full release/Android Auto runtime qualification is not claimed.

## Changes Implemented

### Gradle wrapper and distribution

- `gradle/wrapper/gradle-wrapper.properties` now points to `gradle-9.6.1-bin.zip`.
- `distributionSha256Sum` is the official checksum `9c0f7faeeb306cb14e4279a3e084ca6b596894089a0638e68a07c945a32c9e14`.
- The wrapper JAR was regenerated from the Gradle 9.6.1 distribution; its SHA-256 is `497c8c2a7e5031f6aa847f88104aa80a93532ec32ee17bdb8d1d2f67a194a9c7`, matching the official Gradle 9.6.1 wrapper checksum.
- `gradlew` and `gradlew.bat` were regenerated by Gradle 9.6.1. No wrapper binary was downloaded from an unofficial source.

### Version catalog and plugin declarations

- `agp = 9.5.3`, `kotlin = 2.4.21`, `ksp = 2.3.14`, `lifecycle = 2.10.0`.
- Removed the `org.jetbrains.kotlin.android` plugin alias from `gradle/libs.versions.toml` and from the root/module `plugins` blocks.
- Kept `org.jetbrains.kotlin.jvm` for the Android-independent `:core` module.
- Kept `org.jetbrains.kotlin.plugin.compose` and `com.google.devtools.ksp`; both are compatible with built-in Kotlin.
- Effective Kotlin runtime on the app classpath is `kotlin-stdlib:2.4.21`, confirming KGP 2.4.21 resolution.

### Built-in Kotlin and JVM targets

- The app module no longer applies the Kotlin Android plugin; AGP compiles Kotlin directly (output under `app/build/intermediates/built_in_kotlinc/...`).
- `kotlinOptions` is not used. Removed the explicit app `kotlin.compilerOptions.jvmTarget` line because built-in Kotlin defaults it to `android.compileOptions.targetCompatibility`, avoiding drift.
- Added `java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }` to both modules; Java source/target remains 17. `:core` also retains explicit Kotlin `JvmTarget.JVM_17`.
- Verified generated class-file major version 61 (Java 17) for app Kotlin, app Java and `:core` Kotlin classes.

### AGP DSL and configuration flags

- The build uses the public `android` DSL only. There is no `BaseExtension`, `applicationVariants`, `libraryVariants`, `testVariants`, `unitTestVariants`, `variantFilter`, eager task mutation or internal AGP API usage.
- Removed `buildToolsVersion = "36.0.0"` because AGP 9.5 defaults to exactly Build Tools 36.0.0.
- Removed redundant `android.useAndroidX` and `android.nonTransitiveRClass` properties; AGP 9 enables both by default.
- Did not add `android.builtInKotlin`, `android.newDsl`, `android.uniquePackageNames` or `android.enableAppCompileTimeRClass`; AGP 9 defaults are used.
- Kept `buildConfig = true` because Settings displays `BuildConfig.VERSION_NAME`; `resValues` remains disabled because it is unused.
- Kept explicit `targetSdk = 36`; `minSdk = 29` and `compileSdk = 36` unchanged.
- Kept release `isMinifyEnabled = true` with the same `proguard-android-optimize.txt` + project rules. Resource shrinking remains disabled, preserving existing release policy; AGP 9's optimized-resource-shrinking and strict R8 keep-rule defaults did not cause R8 failures.

### Compose, Room and KSP

- Compose compilation succeeds with the Kotlin 2.4.21 Compose compiler plugin and the unchanged Compose BOM 2025.10.01.
- Room 2.8.3 annotation processing succeeds under KSP 2.3.14. The checked-in schema `app/schemas/org.melodee.android.data.PlaybackDatabase/1.json` is unchanged; no destructive migration was introduced.
- KSP 2.3.14 exceeds Google's AGP 9 requirement of KSP 2.3.6 and is independent of the Kotlin compiler version.
- Lifecycle was moved to 2.10.0 because 2.9.4's lint issue registry referenced Kotlin compiler APIs unavailable in the AGP 9.5 lint runtime, causing `UnsafeLifecycleWhenUsage` and `RepeatOnLifecycleWrongUsage` to be skipped. 2.10.0 fixes the registry while keeping `minCompileSdk=35`; 2.11.x requires compileSdk 37 and was rejected.

### Source-only warning correction

Three uses of the deprecated `Icons.Rounded.QueueMusic` were replaced with `Icons.AutoMirrored.Rounded.QueueMusic` (BrowseScreens.kt and PlayerScreens.kt) so the migrated Kotlin compiler emits no deprecation warnings. The icon now follows Compose's auto-mirroring guidance; layout, size and Melodee branding are unchanged.

### CI/CD

- The main workflow keeps JDK 21 (Temurin) and the repository wrapper via `gradle/actions/setup-gradle@v4`.
- The verification command now also assembles the R8 release APK: `:core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease`.
- The optional emulator job now uses API 36 instead of API 35, matching compile/target SDK 36 while still testing a device above minimum API 29.
- No quality gate was removed, no test excluded, and no external service or credential was introduced.

### Documentation and decisions

- Added [ADR-0010](docs/adr/0010-modern-build-toolchain.md) documenting the new baseline and superseding the build baseline in ADR-0007. ADR-0001 through ADR-0003 and the other product decisions were not altered.
- Updated the ADR index, README, SPEC, IMPLEMENTATION, VALIDATION and AGENTS with the new versions, JDK/Studio requirements and build constraints.
- The Room schema, application ID, label, icon, manifest, Media3 session ownership and demo playback code were unchanged.

## Remaining Issues

1. **Android Auto DHU and physical-vehicle qualification are outstanding.** The manifest and MediaLibraryService path are preserved and tested at the API level, but car discovery, host browsing, car search, artwork projection, reconnect and vehicle endurance were not run.
2. **The unsigned release APK was not installed or executed.** Release signing is intentionally not configured and no release key was introduced. The R8-optimized artifact was inspected statically (manifest, resources, assets, classes) but not runtime-qualified.
3. **Android Studio interactive sync was not executed.** Studio Rabbit 2 (`AI-262.10968.63.2622.16840690`, the minimum release supporting AGP 9.5) is installed, but launching and syncing the GUI in this session was not performed. CLI configuration, `help`, `projects`, and dry-run task graph all succeed.
4. **KGP/AGP compatibility-table lag.** The Kotlin documentation lists AGP 9.3.1 as the highest fully supported AGP for KGP 2.4.21, while AGP 9.5.3 is used. AGP 9.5 built-in Kotlin requires KGP 2.2.10+ and AGP 9.6 moves its default to KGP 2.4.20; the full build, unit tests, R8 release, lint and device instrumentation pass. Monitor future AGP/KGP release notes and upgrade as a reviewed change if Google publishes a constraint.
5. **Lint advisories remain intentional.** 25 warnings are dependency-version/toolchain availability notices, deliberate SDK 36 pins, exported media components required for Android Auto, pre-existing icon/resource/KTX suggestions and the unchanged resource-shrinking policy. No warnings are suppressed and none are errors.
6. **Resource shrinking and configuration cache remain disabled.** Both were evaluated and are compatible in principle (configuration cache fully exercised), but enabling either changes existing build/release policy and belongs in a separate measured decision.
7. **Runtime qualification is emulator-only.** Phone validation used an API 37 AVD. Minimum API 29, API 36, physical phones, Bluetooth/calls/audio focus, long-duration playback and low-memory behaviour were not re-qualified in this task.
8. **Lifecycle 2.10.0 is newer than the toolchain mandate required.** It was upgraded only because 2.9.4's lint registry is incompatible with AGP 9.5 lint; 2.11+ would require compileSdk 37.

## Final Recommendation

Adopt AGP 9.5.3, Gradle 9.6.1, Kotlin 2.4.21, KSP 2.3.14, built-in Kotlin and JDK 21 as the official Melodee development baseline. The migration removes the legacy Kotlin Android plugin and AGP 8 compatibility mechanisms, keeps the pinned runtime dependencies stable, preserves the application identity, playback architecture and Android Auto declarations, and passes debug/release builds, unit tests, lint and real phone-emulator instrumentation from a clean no-cache build.

This recommendation covers **development toolchain readiness**, not full production qualification. Android Auto DHU/vehicle testing, runtime validation of the signed release artifact and broader device/API coverage remain required before a production release claim.
